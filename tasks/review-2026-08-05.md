## 2. Findings, ranked

### P0-1 — MR-1 is blocked by an undecided write path (money-rail success metric #1)

`prd-money-rail.md` §Phase roadmap calls MR-1 *"Ready for SOS (infra done)"*, but the only write
endpoint is `http://127.0.0.1:9545` on the Mac mini. The open question at line 131 ("expose a
stable tunnel/URL for SOS writes off-box, or keep SOS colocated?") is unanswered; the T5 spike in
`plan-parallel-integration.md:78` was never dispatched, D-0017 closed the program without it, and
`prd-mainnet-pilot.md:35` re-parks it as "T5 revival". Two docs (`coordination-settlementos.md:20`,
money-rail G3) describe writes as going to "loopback or future tunnel" — which is not an
integration contract SOS can build against.

Impact: MR-1 acceptance, the settle demo, and P7-4 all sit behind this one unmade decision.
It is also the cheapest item on the list — it is a written decision, not an implementation.

**Attached finding (security, applies to whatever transport wins):** the sequencer's HTTP/WS RPC
runs with `--http.api=eth,net,web3,debug,txpool,admin,miner` and `--http.vhosts="*"` /
`--http.corsdomain="*"` ([04-start-sequencer-sepolia.sh:41](scripts/04-start-sequencer-sepolia.sh)),
and op-node with `--rpc.enable-admin` (line 87). Correct for loopback; unacceptable the moment the
port is reachable, since it exposes `admin_*`, `debug_*` and `miner_*` on the sequencer with
DNS-rebinding protection off. Narrowing this to a write-facing `eth,net,web3` endpoint is the
first T5 deliverable and is independent of the tunnel choice — see R-01 §D1.

### P0-2 — `deployments/rail-interface.json` is stale and misleading in three specific places

This is the single artifact the money-rail PRD promises as the SOS contract (FR-2). It says
`"version": "1", "updated": "2026-07-24"`. Since then Phase 6 completed, D-0016 established that
the replica has no reachable URL, and D-0018 changed what happens after the pin. Concretely wrong:

   today cannot tell whether the pin has expired and a redeploy is imminent. (It has not — D-0018
   keeps 852 as staging — but the file doesn't say so.)
2. `replica.readRpcUrl: "operator-configured (Render private service / shell; not committed)"` and
   `healthChecks.replica` telling the consumer to run `replica-sync-check.sh` with
   `REPLICA_L2_RPC_URL`. Per D-0016 **no such URL exists and none can be created** — Render `pserv`
   with no public URL and no working SSH tunnel. MR-2 ("document replica as preferred read path;
   optional read URL in rail interface") is marked "Ready" in the PRD but is in fact undeliverable
   as written.
3. No availability information at all — see P0-3.

Also missing for a real integrator: L2 block time, native currency, withdrawal/challenge delay
values, and a genesis/rollup hash a counterparty could pin. And the PRD's own open question
(`networkId` = `fortel2-sepolia` vs `forte-l2`) is still open while the file already ships a value.
